📋 Overview

This implementation provides simple Telegram authentication for your GitHub Pages site using:

  • Telegram WebApp API - Get user data from Telegram
  • Supabase JS SDK - Store/retrieve player data
  • Vanilla JavaScript - Pure frontend, no backend needed
  • RLS Policies - Secure database access

Features

  • ✅ Auto-create profiles on first login
  • ✅ Create player_balances, settings, VIP automatically
  • ✅ Handle existing players (update last_seen_at)
  • ✅ Prevent duplicate profiles (UNIQUE constraint)
  • ✅ Ban/delete detection
  • ✅ Real data display on profile page
  • ✅ localStorage cache for offline browsing
  • ✅ No backend Edge Functions needed

⚙️ Setup Guide

Step 1: Get Supabase Credentials

  1. Go to: https://app.supabase.com/
  2. Select your project
  3. Go to: Settings → API
  4. Copy:
    • Project URL → Your SUPABASE_URL
    • anon public → Your SUPABASE_ANON_KEY

Step 2: Update Configuration Files

Replace in index.html (around line 330):

TelegramAuth.setConfig({
  supabaseUrl: 'https://xxxxx.supabase.co',  // PASTE YOUR URL
  supabaseAnonKey: 'eyJhbGci...',             // PASTE YOUR KEY
});

Replace in profile.html (around line 350):

TelegramAuth.setConfig({
  supabaseUrl: 'https://xxxxx.supabase.co',  // SAME URL
  supabaseAnonKey: 'eyJhbGci...',             // SAME KEY
});
⚠️ SECURITY: These are PUBLIC keys (anon). It's safe to have them in frontend code. NEVER put your service_role_key in frontend!

Step 3: Create Telegram Bot

  1. Open Telegram → Search: @BotFather
  2. Send: /newbot
  3. Choose bot name & username
  4. Save your TELEGRAM_BOT_TOKEN (you'll need it later)
  5. Send: /setmenubutton
  6. Select your bot
  7. Choose: Web App
  8. Set URL to: https://yourusername.github.io/Black%20Russia%20Online/

Step 4: Deploy SQL Changes

See section below "RLS Policies" for required SQL.

Step 5: Push to GitHub Pages

git add .
git commit -m "Add Telegram authentication"
git push origin main

Step 6: Test in Telegram

  1. Open your Telegram bot
  2. Click the Web App button
  3. User should auto-login and see real profile data
  4. Check Supabase to verify new profiles were created

🔒 RLS Policies Setup (CRITICAL!)

⚠️ YOU MUST DO THIS! Without these policies, the frontend cannot create profiles.

Run This SQL in Supabase

  1. Go to: Supabase Dashboard → SQL Editor
  2. Click: "New Query"
  3. Paste the SQL below
  4. Click: "Run"
-- ============================================================
-- TELEGRAM AUTH - RLS POLICIES for FRONTEND
-- ============================================================

-- 1. Allow INSERT for new profiles (anon user)
CREATE POLICY "allow_create_profile" ON public.profiles
FOR INSERT
TO anon
WITH CHECK (true);

-- 2. Allow INSERT for player_balances
CREATE POLICY "allow_create_balance" ON public.player_balances
FOR INSERT
TO anon
WITH CHECK (true);

-- 3. Allow INSERT for player_settings
CREATE POLICY "allow_create_settings" ON public.player_settings
FOR INSERT
TO anon
WITH CHECK (true);

-- 4. Allow INSERT for player_vip
CREATE POLICY "allow_create_vip" ON public.player_vip
FOR INSERT
TO anon
WITH CHECK (true);

-- 5. Allow SELECT profiles by telegram_id
CREATE POLICY "allow_read_profiles" ON public.profiles
FOR SELECT
TO anon
USING (true);

-- 6. Allow UPDATE profile status (for login)
CREATE POLICY "allow_update_profile_status" ON public.profiles
FOR UPDATE
TO anon
USING (true)
WITH CHECK (true);
✅ What these policies do:
  • Allow anonymous users to CREATE profiles (once, due to UNIQUE constraint)
  • Allow anonymous users to READ profiles
  • Allow anonymous users to UPDATE profile status/last_seen_at
  • Do NOT allow DELETE or UPDATE balance/level (protected for later)

If You Get Errors

If policies already exist, delete them first:

DROP POLICY IF EXISTS "allow_create_profile" ON public.profiles;
DROP POLICY IF EXISTS "allow_create_balance" ON public.player_balances;
DROP POLICY IF EXISTS "allow_create_settings" ON public.player_settings;
DROP POLICY IF EXISTS "allow_create_vip" ON public.player_vip;
DROP POLICY IF EXISTS "allow_read_profiles" ON public.profiles;
DROP POLICY IF EXISTS "allow_update_profile_status" ON public.profiles;

Then run the CREATE POLICY statements above.

💻 Usage Examples

In Any Page Script

// Initialize auth
await TelegramAuth.init();

// Check if authorized
if (TelegramAuth.isAuthorized()) {
  // Get Telegram user
  const user = TelegramAuth.getCurrentUser();
  console.log(user.id, user.username, user.first_name);

  // Get full profile with balance & vip
  const { profile, balance, vip, settings } = TelegramAuth.getCurrentProfile();
  
  console.log('Profile:', profile.nickname, profile.level);
  console.log('Balance:', balance.cash, balance.bank);
  console.log('VIP:', vip.vip_level);
} else {
  console.log('User not authorized');
}

Listen to Auth Ready Event

document.addEventListener('telegramAuthReady', (event) => {
  const { user, profile } = event.detail;
  console.log('User:', user.username);
  console.log('Profile UID:', profile.profile.uid);
  
  // Update UI with real data
  document.querySelector('.profile-name').textContent = profile.profile.nickname;
});

Get Specific Data

// Get profile only
const profile = TelegramAuth.getProfile();
console.log(profile.nickname, profile.level);

// Get balance
const balance = TelegramAuth.getBalance();
console.log('Cash:', balance.cash, 'Bank:', balance.bank);

// Get VIP
const vip = TelegramAuth.getVip();
console.log('VIP Level:', vip.vip_level);

// Check if banned
if (TelegramAuth.isBanned()) {
  alert('Account banned!');
}

// Logout
TelegramAuth.logout();

What Happens on Login

User opens Telegram Mini App
    ↓
TelegramAuth.init() called
    ↓
Extracts Telegram.WebApp.initDataUnsafe.user
    ↓
Searches profiles WHERE telegram_id = user.id
    ↓
IF NOT EXISTS:
  CREATE profiles (nickname, level=1, experience=0, etc)
  CREATE player_balances (cash=0, bank=0)
  CREATE player_settings (notifications=true, etc)
  CREATE player_vip (level=0, expires_at=NULL)
  ↓
IF EXISTS:
  Check is_banned → reject if true
  Check is_deleted → reject if true
  UPDATE status='online', last_seen_at=now()
  ↓
FETCH all data (profile + balance + vip + settings)
    ↓
Save to localStorage (cache only)
    ↓
Dispatch 'telegramAuthReady' event
    ↓
UI updates with real data
    ↓
✓ User logged in successfully

🐛 Troubleshooting

❌ "Supabase SDK not loaded"

Cause: Supabase script loaded after auth.js

Fix: In HTML HEAD, order should be:

<head>
  ...
  <!-- Supabase BEFORE auth.js -->
  <script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
  
  <!-- Auth AFTER Supabase -->
  <script src="js/auth.js"></script>
</head>

❌ "No Telegram user available" (in browser)

Cause: Telegram WebApp only works inside Telegram app, not in regular browser

Solution: This is expected in browser. In Telegram it will work.

For testing: Mock Telegram in console:

window.Telegram = {
  WebApp: {
    ready: () => {},
    initDataUnsafe: {
      user: {
        id: 123456789,
        username: 'testuser',
        first_name: 'Test',
        photo_url: null,
      }
    },
    initData: 'auth_date=123456&hash=abc123',
  }
};

❌ "UNIQUE violation on telegram_id"

Cause: Two login requests at exact same time

Solution: Handled automatically. Auth.js catches error and fetches existing profile.

❌ RLS Policy Errors

Cause: Policies don't exist or are incorrect

Solution: Run the SQL from section "RLS Policies Setup" above

❌ Wrong Supabase credentials

Solution: Check that you copied:

  • URL from: Settings → API → "Project URL"
  • Key from: Settings → API → "anon public" (NOT service_role!)

❌ Profile shows "Dima" instead of real username

Cause: Auth initialized after profile.html's data loader

Solution: Refresh page or wait for 'telegramAuthReady' event before displaying

❌ "is_banned / is_deleted" error shows

Cause: User account is banned or deleted in database

Solution: Admin must unban in Supabase: 

UPDATE profiles SET is_banned = false WHERE uid = 123;

❌ localStorage is not working

Cause: Browser privacy settings or storage quota exceeded

Solution: Auth still works - localStorage is just cache. Check browser console for errors.
